# 08 · island chart

A Chart.js line chart inside a lit island, fed live from the server. A
goroutine adds a made-up requests-per-second reading every second and
keeps the last 60; buttons pick how many of them every open chart shows.
The page renders a plain-HTML fallback that the island replaces.

```sh
npm install
go tool templatic generate
go run .                     # http://localhost:8080
```

Open it in two windows and press a button in one.

## What it shows

- **The pragma makes a component an island.** In
  `components/chart.templ`, `//templatic:island tag=traffic-chart
  props=ChartProps variant=lit ...` sits above `TrafficChart`. `generate`
  writes `components/chart_tc.go` with `TrafficChartIsland(props)`, which
  `components/home.templ` renders (it is `ui.Island` with the tag filled
  in).
- **The component body is the fallback.** `TrafficChart` renders the
  latest value and a table of the last five seconds. That is the first
  paint and all a page without JavaScript gets; the lit element clears it
  when it mounts and renders the chart instead.
- **Binds push cells into props.** `bind=series:traffic.series
  bind=window:traffic.window` ties two world cells (declared in
  `traffic.go`) to the props fields with those json names. On every
  change the island gets a new `props` object and lit calls `updated()`,
  where the define module updates the chart. `generate` refuses a bind
  whose field is not a json name of the props struct or whose topic is no
  declared cell; it does not compare the cell's type with the field's
  ([#10](https://github.com/nkapatos/templatic/issues/10)).
- **The whole series is one value.** Values are latest-wins and published
  whole ([design.md](../../design.md#the-live-channel)), so each second
  the full series of up to 60 numbers goes to every page with the chart;
  `/about` has none and receives none of it. That is fine for a short
  window; a dataset that grows without bound is a keyed list, not a value.
- **The props type comes from Go.** `ChartProps` in
  `components/traffic.go` becomes `.templatic/islands/traffic-chart.types.ts`,
  imported as `templatic/islands/traffic-chart.types` in
  `client/islands/traffic-chart.ts`. There is no hand-written twin:
  renaming a json field breaks the TypeScript build (`check-ts`).
- **The define module is yours.** `generate` wrote
  `client/islands/traffic-chart.ts` once, extending the generated
  `TrafficChartBase` (in `.templatic/islands`, regenerated every run). It
  implements `render()` and `updated()` and destroys the chart on
  disconnect.
- **The chart library loads only where the island is used.** `chart.js`
  is an ordinary dependency in `package.json`, imported only by the
  define module, so it is bundled into
  `.templatic/dist/islands/traffic-chart-*.js` together with lit (about
  155 KB, 55 KB gzipped). The boot module and the shared chunk carry the
  runtime only. `Boot` adds a modulepreload for the island's file on the
  chart page; `/about` has no island and loads only the boot module, the
  chunk and the stylesheet (see `.templatic/dist/tc.json`).
- **A second control.** `ui.Button(SetWindow, WindowIn{Points: n})` sets
  the `traffic.window` cell; its bind changes the visible window on every
  open chart. Buttons need JavaScript, as in
  [02](../02-live-value).

## Files

| File | Holds |
|---|---|
| `main.go` | the world, the sampling goroutine, the mux and the asset handlers |
| `traffic.go` | the two cells, the `SetWindow` handler, the sampler |
| `components/traffic.go` | `ChartProps`, `SetWindow` and `WindowIn` |
| `components/chart.templ` | the island pragma and its fallback markup |
| `components/home.templ` | the chart page and the page without an island |
| `components/layout.templ` | the document, `Head`, `Boot` |
| `client/islands/traffic-chart.ts` | the lit element that draws the chart |
| `client/app.ts`, `client/app.css` | the bundle's sources |
| `public/favicon.svg` | a file the app serves itself |

`*_templ.go` and `*_tc.go` files are generated by `templatic generate` and
committed. `.templatic/` is generated and ignored.
