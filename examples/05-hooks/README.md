# 05 · hooks

Client-only behavior with hooks: a menu, a light/dark theme toggle and a
modal help dialog run in the browser with no request to the server. Each
one works without JavaScript too, through plain HTML and a form POST. One
server-swapped card shows hooks mounting on markup that arrives later.

```sh
npm install
go tool templatic generate
go run .                     # http://localhost:8080
```

## What it shows

- **A hook is a TypeScript module plus an attribute.** `defineHook(name,
  callbacks)` from `"templatic"` (`client/menu.ts`, `client/theme.ts`,
  `client/dialog.ts`, imported by `client/app.ts`); `ui.Hook(name, args)`
  marks the element in the markup (`components/layout.templ`,
  `components/pages.templ`) and JSON-encodes `args` into
  `data-tc-hook-args`.
- **`mounted` gets the element, its args and an AbortSignal.** Every
  listener here is added with `{ signal }`. The signal aborts when the hook
  is destroyed (its element leaves the page), which removes listeners on
  `document` too; the hooks need no `destroyed` callback. The other
  callbacks are `beforeUpdate`, `updated`, `destroyed`, `disconnected` and
  `reconnected`.
- **Menu: a `<details>` element.** Open, close and the expanded state are
  native, with or without JS. The `menu` hook adds Escape (focus returns to
  the summary) and closing on a click outside.
- **Theme: a cookie the server reads.** `components.PageFor` reads the
  `theme` cookie and the layout renders `<html data-theme="dark">`, so the
  first paint is right with no flash. The toggle is a form that POSTs
  `/theme` (`components.SetTheme` sets the cookie and redirects back); the
  `theme` hook cancels that submit, sets `data-theme` and writes the same
  cookie from the browser.
- **Dialog: a link to `/help` and a `<dialog>` on the page.** Without JS
  the link opens the help page; the `dialog` hook opens the same content
  with `showModal()` instead, which brings Escape and the focus trap. The
  hook adds closing on a backdrop click. Modified clicks still open the page.
- **Hooks mount on swapped-in markup.** The tip card is a session region
  (`live.DeclareSessionRegion`, `components/tips.go`); "Next tip" is a
  `ui.Link` to the `tip.show` command, which swaps the next card into this
  page and moves the URL with `live.At`. Each card has its own id, so the
  swap inserts a new element: the old card's hook is destroyed and the
  `menu` hook mounts on the new one. Without JS the link loads `/?tip=N`.

## Files

| File | Holds |
|---|---|
| `main.go` | the mux, the world, the `tip.show` handler |
| `components/page.go` | the theme cookie, `PageFor`, `SetTheme`, the hooks' Go args |
| `components/tips.go` | the tips, the `tip` session region and the `tip.show` command |
| `components/layout.templ` | the document, the menu and the theme toggle |
| `components/pages.templ` | the home page with the dialog and tip card, the help page |
| `client/menu.ts`, `client/theme.ts`, `client/dialog.ts` | the three hooks |
| `client/app.ts`, `client/app.css` | the bundle's entry and stylesheet |

`*_templ.go` files are generated by `templatic generate` and committed;
`.templatic/` is generated and ignored.

Hook args are typed twice: a Go struct passed to `ui.Hook` and a
hand-written TypeScript interface given to `defineHook<A>`. Nothing checks
that they agree
([#11](https://github.com/nkapatos/templatic/issues/11)).
