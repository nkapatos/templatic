# 01 · pages

Static templ pages with templatic's bundled, fingerprinted assets. No live
state: there is no `live.World`, so nothing connects back to the server.

```sh
npm install
go tool templatic generate
go run .                     # http://localhost:8080
```

## What it shows

- **Pages are templ components** served by `templ.Handler` on a plain
  `http.ServeMux` (`main.go`). templatic does not route.
- **CSS goes through the bundle.** `client/app.ts` imports `client/app.css`;
  `templatic generate` writes it as `app-<hash>.css`, and
  `templatic.Head` links it from the manifest (`.templatic/dist/tc.json`).
- **Images referenced by the CSS are bundled too.** `url(./logo.svg)` becomes
  `assets/logo-<hash>.svg`. From markup, `templatic.Asset(ctx, "client/logo.svg")`
  returns the same hashed URL, from the manifest `templatic.App` puts in
  the request, so it follows rebuilds under `templatic dev`.
- **Hashed files are cached for a year.** `templatic.Assets` serves the dist
  directory with `Cache-Control: immutable` on hashed names; a changed file
  gets a new name, so a deploy never serves a stale one.
- **No World, no live layer.** `templatic.App(nil, manifests, mux)` adds only
  the manifest; `Boot` still loads the runtime, which skips the live channel
  on a page without a page token.
- **The app's own files stay the app's.** `public/` is served by the app's
  `http.FileServer` under `/static/`, outside the bundle.

## Files

| File | Holds |
|---|---|
| `main.go` | the mux, the manifest, the asset handlers |
| `components/layout.templ` | the document, `Head`, `Boot`, the menu |
| `components/pages.templ` | the home, about and not-found pages |
| `client/app.ts`, `client/app.css`, `client/logo.svg` | the bundle's sources |
| `public/favicon.svg` | a file the app serves itself |

`*_templ.go` files are generated by `templatic generate` and committed, as
with templ. `.templatic/` is generated and ignored.

Note: `templatic.Asset` does not follow `templatic dev` rebuilds yet
([#27](https://github.com/nkapatos/templatic/issues/27)); restart the server
after changing an image.
