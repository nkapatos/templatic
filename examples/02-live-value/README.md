# 02 · live value

One live value on every open page: the level of a shared tank. The server
drains it by one every second; anyone can fill or empty it with a button.
Every open page, for every viewer, shows the same level as it changes.

```sh
npm install
go tool templatic generate
go run .                     # http://localhost:8080
```

Open it in two windows and press a button in one.

## What it shows

- **A world cell is shared state.** `live.NewCell(w, "tank.level", 50)` in
  `tank.go` declares one value for the whole world: every page that shows
  it gets its changes, whoever the page belongs to.
- **`ui.Cell` renders it and keeps it live.** `components/home.templ`
  renders the current value on the server; the runtime replaces the text
  when the cell changes.
- **`ui.CellAttr` puts the same value in an attribute.** The `<meter>` in
  `components/home.templ` spreads `ui.CellAttr(level, "value")`, so its
  bar follows the cell. Only `data-*`, `aria-*`, `class` and `value` can
  be bound.
- **The server changes it on its own.** `drain` in `tank.go` is a plain
  goroutine with a ticker calling `level.Update`; nothing about it is
  request-scoped.
- **A button changes it too.** `ui.Button(Fill, FillIn{Amount: 10}, …)`
  sends the `tank.fill` command with a fixed input. `Empty` takes
  `struct{}`. No field to fill: the input is fixed in the markup. Input
  still goes through `FillIn.Validate`.
- **Values are latest-wins.** A burst of changes to one value sends the
  last one ([design.md](../../design.md#the-live-channel), "The live
  channel"): changes that land in the same flush window
  (`live.WithCoalesceWindow`, 8ms by default) reach the page as one
  event. A cell is published whole on every change, so each event
  carries the full value.
- **The buttons work without JavaScript.** `ui.PostTo("/fill")` makes
  each `ui.Button` a one-button form that posts its fixed input, and
  `Fill.Form` and `Empty.Form` in `tank.go` serve the POST either way:
  with JavaScript the page stays and the level updates live; without, the
  browser is sent back to the page, which renders the new level. Forms
  with fields are 03's topic.
- **The command handlers are tested without a browser.** `tank_test.go`
  posts to them as the runtime does (`livetest.Session.PostForm`) and
  reads the pushed value.

## Files

| File | Holds |
|---|---|
| `main.go` | the world, the drain goroutine, the mux and the asset handlers |
| `tank.go` | the cell, the command handlers, the drain loop |
| `tank_test.go` | the handlers tested with `livetest` |
| `components/tank.go` | the `Fill` and `Empty` commands and `FillIn` |
| `components/home.templ` | the page: the cell, the meter, the buttons |
| `components/layout.templ` | the document, `Head`, `Boot` |
| `client/app.ts`, `client/app.css` | the bundle's sources |
| `public/favicon.svg` | a file the app serves itself |

`*_templ.go` files are generated by `templatic generate` and committed, as
with templ. `.templatic/` is generated and ignored.
