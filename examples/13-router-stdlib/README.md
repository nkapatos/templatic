# 13 · router (stdlib)

A short list of items, each with a page at `/items/{id}` and a live like
count. Liking an item updates the count on every open page, the list
included; the like button works without JavaScript too. The same app runs
on chi in [13-router-chi](../13-router-chi) and on echo in
[13-router-echo](../13-router-echo): only `routes` in `main.go` differs.

```sh
npm install
go tool templatic generate
go run .                     # http://localhost:8080
```

Open the list in one window and an item in another, then like it; then
turn JavaScript off and like it again.

## What it shows

- **Routing is the app's.** `routes` in `main.go` is the only function
  that knows the router: it mounts the feature's handlers, the world and
  the two file servers on a `http.ServeMux`, and `templatic.App` wraps
  whatever it returns. `diff` this example's `main.go` against the chi or
  echo one to see the whole difference.
- **`World.Mount(mux, "/live")`** registers `GET /live/stream` (`w.SSE()`)
  and `POST /live/commands` (`w.Commands()`); Boot's `Live: "/live"` in
  `internal/page/layout.templ` names the same base.
- **A feature is one package.** `internal/items` holds the declarations
  and `Register` (`feature.go`), the data (`model.go`) and the views
  (`pages.templ`). `Register` declares the state and the command handler
  on the world and returns plain `http.Handler`s; it does not take a
  router, so it does not care which one mounts it. The shared document
  and the 404 page are in `internal/page`.
- **The id comes from the path.** `Show` reads `r.PathValue("id")`.
  `Like.Form` decodes the form and lets route wildcards win over form
  fields, so a POST to `/items/1/like` likes item 1 whatever its `id`
  field says, with and without JavaScript. `TestLikeFormUsesThePathID` in `main_test.go`
  posts a forged `id` through `routes`.
- **One cell per item.** `live.NewCellFamily(w, "likes", 0)` declares a
  cell for each item on first use; `ui.Cell(likes.Get(id))` renders it on
  the list and on the item page, and both follow every like.
- **Not found.** `GET /items/9` renders the 404 page; liking an unknown
  item returns `live.NotFound`, a 404 on both transports.

## Files

| File | Holds |
|---|---|
| `main.go` | the world, the manifest and `routes`: the ServeMux wiring |
| `main_test.go` | the path id beats a forged field; unknown items are 404 |
| `internal/items/feature.go` | `Like`, `LikeIn`, `Register` and the handlers it returns |
| `internal/items/model.go` | the fixed catalog and `find` |
| `internal/items/pages.templ` | the list and the item page |
| `internal/page/layout.templ` | the document, `Head`, `Boot`, the 404 page |
| `client/app.ts`, `client/app.css` | the bundle's sources |
| `public/favicon.svg` | a file the app serves itself |

`*_templ.go` files are generated by `templatic generate` and committed, as
with templ. `.templatic/` is generated and ignored.
