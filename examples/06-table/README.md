# 06 · table

A server-driven table of a few hundred orders with paging, search and sort
by column, all in the URL (`/?page=2&q=acme&sort=amount&dir=desc`). A
server goroutine changes a few orders every three seconds, and every open
page redraws its table with its own page, sort and search. Without
JavaScript every link and the search form are plain page loads.

```sh
npm install
go tool templatic generate
go run .                     # http://localhost:8080
```

## What it shows

- **The URL pattern from [04-url-state](../04-url-state).** `View`
  (`components/orders.go`) is page, search, sort and direction; `ParseView`
  reads it from the query, `View.URL` writes it back, `Navigate` swaps the
  table and returns `live.At(v.URL())`. The column headers are
  `ui.Link(Navigate, v.SortedBy(col), ...)`: a click on the sorted column
  flips the direction, another column starts at its default direction on
  page 1. The pager links are `ui.Link` too.
- **Numbers and enums in the query.** `ParseView` reads `page` with
  `strconv.Atoi`; `Clean` keeps it at least 1, and `store.Query`
  (`store.go`) clamps it to the last page, so `?page=999` shows the last
  page. An unknown `sort` or `dir` falls back to the default.
- **Refresh every session with its own view.**
  `TableRegion.Refresh(w, model)` (`main.go`, `table.update`) renders the
  region once per connected session whose page shows it, from what
  `model(s)` returns. The
  view each session shows is kept in a server-only session value,
  `viewOf` (`live.DeclareSessionValue`): `World.OnConnect` seeds it from
  `Session.URL()` (the address the page was loaded at) and `navigate`
  sets it on every swap.
- **Search is a plain GET form with a hook, outside the region.** Neither
  a swap nor a refresh morphs the search box, so what is being typed
  stays. Without JS the form GETs `/?q=…`, the same page route. With JS the
  `search` hook (`client/search.ts`) raises `Navigate` instead, on submit
  and once typing pauses, and sets the fields from the URL after every
  other navigation, back and forward included. As in 04, each search it
  raises is a history entry of its own
  ([#61](https://github.com/nkapatos/templatic/issues/61)).
- **World cells next to session regions.** The row count and the time of
  the last change are world `live.Cell`s shown with `ui.Cell`, as in
  [02-live-value](../02-live-value). Rows changed by the latest update are
  highlighted.
- **Tests through livetest.** `main_test.go` checks `ParseView` and its
  round trip through `View.URL`, and that an update refreshes two sessions,
  one moved by `Navigate` and one connected at a deep link, each with its
  own view.

The query is parsed by hand: there is no typed query decoding yet
([#5](https://github.com/nkapatos/templatic/issues/5)). Fast
clicks can leave the address and the table out of step, as in 04
([#34](https://github.com/nkapatos/templatic/issues/34)).

## Files

| File | Holds |
|---|---|
| `main.go` | the world, `Navigate`, the update loop and `Refresh`, the routes |
| `store.go` | the generated orders, the changes, search, sort and paging |
| `main_test.go` | the view parsing and per-session refresh tests |
| `components/orders.go` | `Order`, `View` and its parsing, `Result`, `Navigate` |
| `components/orders.templ` | the page with the search form, the `Table` region |
| `components/layout.templ` | the document, `Head`, `Boot` |
| `client/search.ts` | the `search` hook |
| `client/app.ts`, `client/app.css` | the bundle's entry and stylesheet |
| `public/favicon.svg` | a file the app serves itself |

`*_templ.go` and `*_tc.go` files are generated by `templatic generate` and
committed. `.templatic/` is generated and ignored.
